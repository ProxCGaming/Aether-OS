# ADR 0008: Phase 3.5 Reachability Filtering, Capability Synthesis, and Auto-Routing

## Status
Accepted

## Context
In previous iterations, model discovery populated candidate lists without verifying actual credential entitlement or endpoint availability, leading to runtime failures on deprecated or unentitled model variants. Furthermore, capability classification was static, and task dispatching lacked automatic intent-based routing across heterogeneous providers.

Key requirements:
1. "Always validate cheaply before attempting expensively": fast, 1-token reachability probe with concurrency control (`asyncio.Semaphore`) and SQLite caching.
2. Capability evaluation synthesis combining Option A (curated public benchmarks) and Option C (live empirical self-test evals via LiteLLM).
3. Transparent Capability Router dispatching tasks to the optimal reachable model based on intent analysis (code, reasoning, vision, chat) and provider health.
4. Comprehensive audit logging for all automatic fallback events.
5. On-demand model list re-querying ("↻ Refresh") and user guidance in the UI.

## Decision

1. **Cheap-First Reachability Filter (`ModelReachabilityChecker`)**:
   - Implemented in `aether_engine/models/reachability.py`.
   - Probes candidate models using `max_tokens=1` with `"hi"` prompt via LiteLLM.
   - Results are cached in `~/.aether/reachability.db` with a 24-hour TTL.
   - Concurrency is throttled to 5 concurrent probes (`asyncio.Semaphore(5)`) to prevent 429 rate limiting.
   - Live model discovery (`fetch_available_models`) defaults to filtering out unreachable models.

2. **Option A + Option C Capability Synthesis**:
   - `aether_engine/capability/benchmark_cache.py`: Curated zero-cost benchmark cache (MMLU, HumanEval, MATH) for known foundation models.
   - `aether_engine/capability/test_suite/evals.py`: Deterministic test suite evaluating arithmetic reasoning, code generation, and instruction obedience.
   - `aether_engine/capability/self_test.py`: Concurrency-controlled live evaluation runner across reachable models.
   - `aether_engine/capability/classifier.py`: Synthesizes evidence from both options into deterministic capability tags (`chat`, `code`, `reasoning`, `fast`, `tools`, `vision`) and performance tiers (`fast`, `balanced`, `premium`).

3. **Capability Router (`CapabilityRouter`)**:
   - Implemented in `aether_engine/routing/capability_router.py`.
   - Analyzes prompt intent using transparent regex pattern banks and token heuristics.
   - Filters candidate models for healthy, configured providers and scores them based on tag match, tier alignment, and health status.

4. **Fallback Audit Logging**:
   - Automatic fallback events trigger structured audit log entries (`FALLBACK_TRIGGERED`, `FALLBACK_COMPLETED`, `FALLBACK_FAILED`) via `AuditLogger`.

5. **UI Refresh & User Guidance**:
   - Added `REFRESH_MODELS_REQUEST` / `REFRESH_MODELS_RESPONSE` WebSocket event flow.
   - Added "↻ Refresh" button to the Cloud provider settings panel.
   - Added descriptive help cards and radio tooltips explaining Option A, Option C, and Both in plain English.

## Consequences

### Positive
- Prevents runtime failures on stale, deprecated, or restricted models by probing entitlement cheaply up front.
- Cost-efficient model classification: Option A provides instant baseline metadata, while Option C provides empirical verification on demand.
- Transparent intent-based dispatch routes coding queries to code-capable models and complex logic to reasoning models.
- Fallbacks are fully auditable with zero silent drops.

### Negative / Trade-offs
- Initial un-cached reachability check for large catalogs takes 1–3 seconds during first-time key setup (mitigated by concurrency and 24h SQLite caching).
